# Freezing
これは、過去の自然言語コンペでも多くの使用例がありますが、バックボーンの先頭N層の学習を行わない(Freezing)というものです。deberta-v3-largeは24層のTransformerによって構成されるためそのうち先頭の12層分を固定することで、過学習を抑制できます。今回の入力データに用いている「元の文章」は4種類しかありませんでしたので、これを行わないと特定の文章構造に最適化されてしまい精度が出ませんでした。

```py
def top_half_layer_freeze(module, n_layer):
    for i inrange(0,n_layer//2+1,1):
        for n,p in module.encoder.layer[i].named_parameters():
           p.requires_grad =False
top_half_layer_freeze(deberta_model,24)
```

# stacking (Emsemble)

ご提示の画像は、DeBERTa-v3-largeを特徴量抽出器として使用し、その出力（CLSトークンのプーリング層）をLightGBMの入力として用いるアンサンブル学習のアーキテクチャを示しています。これは一般的なモデルの組み合わせ方であり、以下のように実装されます。

1. 実装の構造
これは、LightGBMをモデルクラス（nn.Linearなど）に直接組み込むのではなく、2つの独立したモデル（DeBERTa-v3とLightGBM）を連携させることで実装されます。

DeBERTa-v3-large:

このモデルは、入力テキストから意味的な特徴量を抽出する特徴量抽出器として機能します。

モデルの最終層（通常は[CLS]トークンの埋め込み）から得られるベクトルを、次のステップの入力として使用します。このベクトルは、テキスト全体の内容を凝縮したものです。

LightGBM:

DeBERTa-v3から抽出されたCLSトークンのベクトルを特徴量として受け取ります。

これらの特徴量を用いて、分類タスク（この場合は二値分類）を学習します。

2. 学習プロセス
学習は、以下の手順で行われます。

特徴量の抽出: まず、DeBERTa-v3-largeモデルをファインチューニングし、学習データ全体（またはクロスバリデーションの各フォールド）のコメントからCLSトークンのベクトルを抽出します。このとき、出力は最終的な予測値ではなく、特徴量ベクトルとなります。

LightGBMの学習: 抽出された特徴量ベクトルと、対応する正解ラベルをLightGBMのモデルに与えて学習させます。図では、3つの異なるLightGBMモデルが学習されており、これは**クロスバリデーション（CV）**の各フォールドで学習されたモデルを示している可能性が高いです。

3. なぜTrainerでは無理なのか？
Hugging FaceのTrainerクラスは、PyTorchやTensorFlowのモデルの訓練を自動化するために設計されています。これは、モデルがnn.Module（PyTorch）のようなニューラルネットワークのクラスとして定義されていることを前提としています。

LightGBMは勾配ブースティング決定木のライブラリであり、PyTorchのnn.Moduleとは全く異なるアーキテクチャを持つため、Trainerに直接組み込むことはできません。

このアーキテクチャは、ニューラルネットワークと勾配ブースティングモデルのハイブリッドであり、それぞれの強みを活かしています。

DeBERTa-v3: テキストの複雑な文脈を理解し、高品質な特徴量を生成する能力に優れています。

LightGBM: 構造化データ（この場合は抽出された特徴量ベクトル）の学習に非常に効率的で、高い性能を発揮します。

4. 図から読み取れること
CLS pooling: DeBERTa-v3の最終層からCLSトークンのベクトルを抽出する処理です。

nn.Linear: DeBERTa-v3の最終分類層です。これは単独で分類器として機能し、そのCVスコア（0.489）が示されています。

2つのLightGBM: 異なるデータ分割で学習された2つのLightGBMモデルが、それぞれ独立した結果（CV: 0.488, 0.491）を出しています。

Ensemble: 最終的に、nn.Linearの予測結果と2つのLightGBMの予測結果を組み合わせて、最終的な予測値を算出しています。これにより、各モデルの予測を統合し、さらに高い精度（CV: 0.477）を目指します。

これは、アンサンブル学習の手法の中でも、**スタッキング（stacking）**と呼ばれる手法に非常に似ています。異なる種類のモデルを組み合わせて、それぞれの予測を新しいモデルの入力として利用することで、モデルの汎化性能を向上させることを目的としています。

# 重要なtextのみのpooing

お考えの通り、[SEP]トークンで区切られた入力のうち、特定のセグメント（今回はruleの後のtext部分）にのみプーリングを適用することで、精度向上を目指すアプローチは有効です。これは、タスクにとって最も重要な情報（本文）にモデルの焦点を絞るためです。

この機能を実装するには、モデルのアーキテクチャや訓練プロセスに直接変更を加える必要があります。具体的には、モデルが出力する全てのトークンの埋め込み（embeddings）から、[SEP]以降のトークンに対応する埋め込みだけを選択してプーリングします。

実装手順
Hugging FaceのTransformersライブラリを使用する場合、このカスタムプーリングはモデルのforwardメソッドをオーバーライドするか、モデルの出力に対して追加の処理を行うことで実現できます。

1. 前処理: token_type_idsの活用
このアプローチをスムーズに行うためには、[SEP]で区切られた各セグメントを識別するための情報が必要です。token_type_idsはそのために理想的な機能です。

入力例: [CLS] rule rule rule [SEP] text text text [SEP]

token_type_ids: [0 0 0 0 1 1 1 1]

rule部分のトークンタイプIDを0に設定。

text部分のトークンタイプIDを1に設定。

2. モデルの出力からtext部分の埋め込みを抽出
token_type_idsをモデルに与えると、モデルの出力（last_hidden_state）は、各トークンに対応する埋め込みベクトルを含みます。この埋め込みから、text部分だけを抽出します。
